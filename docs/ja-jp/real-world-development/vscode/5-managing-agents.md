GitHub Copilot を agent mode で使うと、コードベースを調査し、変更を提案し、ファイルを編集し、コマンドを実行します。VS Code の Copilot Chat では、ツールの呼び出しやファイルの編集をリアルタイムで確認できます。差分を確認して個別の変更を採用または取り消し、エディターを離れずに追加のプロンプトで作業を調整・拡張できます。

このエクササイズでは、次の操作を行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル変更をレビューして採用します。
- セッション中にエージェントを導き、高コントラストに加えてライトモードの切り替えを追加します。

## シナリオ

[エクササイズ 4][previous-lesson]で使ったアクセシビリティカスタムエージェントが、高コントラストモードを実装しています。作業中にデザインチームから追加要望があり、既定のテーマが暗すぎると感じる利用者向けにライトモードの切り替えも追加することになりました。新しい会話を始めず、既存セッションを導いて機能を拡張します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが調査したファイル、実行したコマンド、提案した編集などの各ステップが表示されます。ファイル編集は差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. エクササイズ 4 で使った Copilot Chat ビューに戻ります。
2. エージェントのツール呼び出しを確認できるよう、チャットをスクロールします。ファイルの読み込み、編集、実行を求められたターミナルコマンドが表示されます。
3. 編集案の差分が表示されたら、次の操作を行います。
   - **Keep** を選択して変更を採用します。
   - **Undo** を選択して変更を取り消し、エージェントに再度試させます。
4. チャット上部の **Files changed** を開き、セッション中に変更されたすべてのファイルを確認することもできます。

> [!NOTE]
> ターミナルコマンドの実行などで許可が必要な場合、エージェントは一時停止して **Allow** を表示します。内容を確認し、許可してもよいコマンドだけを承認してください。

5. 高コントラストモードの実装が終わるまで待ちます。最後に変更内容の要約が表示されます。

## エージェントを導いてライトモードを追加する

高コントラストモードができたら、同じ会話でライトモードの切り替えも追加します。会話を続けることで、エージェントは以前の作業で変更したコンポーネント、スタイル、ローカルストレージのパターンを引き継ぎます。

1. Copilot Chat の入力欄に次の追加プロンプトを送信します。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントは既存の変更を調べ、ライトモードの追加を提案します。
3. 高コントラストと同様に、追加された変更を確認し、差分ごとに **Keep** または **Undo** を使います。
4. エージェントの方針 (たとえば、好みと異なるトグル UI のリファクタリング) を修正する必要がある場合は、入力欄の横にある **Stop** ボタンで停止してから、明確な追加プロンプトを送ります。

> [!TIP]
> 作業中のセッションを導く方が、最初からやり直すより早く済みます。追加プロンプトで変更を依頼できます。たとえば「CSS を簡潔にし、セレクターの重複ではなく CSS 変数を使う」「3つ目のトグルは追加せず、ライトモードを既存の設定パネルに統合する」「両モードにキーボードショートカットも追加する」などです。

## 変更セットをレビューする

コミットする前に、エージェントが変更したファイルを確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストが更新されているはずです。
3. いくつかのファイルを開き、差分を確認します。ARIA 属性、キーボード操作、セマンティック HTML、ローカルストレージによる設定の保存など、アクセシビリティのパターンが反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat の agent mode で、進行中のセッションを監視して導きました。各ファイルの編集を確認し、変更を採用または拒否し、コンテキストを保ったまま追加プロンプトで作業を拡張しました。

このレッスンでは、次の操作を行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を採用または取り消しました。
- 追加プロンプトで作業中のセッションを導きました。

次のレッスンでは、アクセシビリティ機能をプルリクエストとして公開し、このラボ全体でローカルカスタムエージェントが作成した変更をレビューします。
